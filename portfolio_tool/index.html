Review Risk Agent

An agent that reads e-wallet complaints and grades them by financial risk instead of star rating — then answers questions about what it found, citing the reviews behind every number. Both panels below are working, not screenshots.

2,339 reviews classified 4 wallets · MoMo, ZaloPay, ShopeePay, Viettel Money — Built, evaluated and written solo · Nov 2026
Tool 01 — the classifier

Grade a complaint, and watch the keyword filter miss it.

Paste any Vietnamese e-wallet review, or pick one below. The agent applies a four-level risk scale and has to quote the exact words it decided on. The same review also goes through a keyword-and-star-rating filter — the cheap approach this project had to beat — so you can see where the two disagree.

Tool 02 — the analyst

Ask the dataset a question.

This agent has three tools over the classified corpus: an overview, a weighted comparison across wallets, and a review search. It decides which to call, and every figure it reports is computed in code — the model never does the arithmetic. Its tool calls are printed under each answer, and review IDs are clickable.

Each wallet’s own weak spot

Shares are weighted and computed within each wallet’s own complaints, so a bigger review base doesn’t inflate them. ZaloPay’s review volume jumped from about 120 to about 3,000 a week in October, with 5-star share going from 35% to 96% — which is exactly why nothing here uses “total reviews” as a denominator.

A fast reply is not the same as help

“Boilerplate” means a reply whose first 70 characters match at least five other replies from the same wallet. ShopeePay answers 98% of complaints using two templates, so this measures automation coverage, not care.

    Evidence — how I know it works

    The agent was tested against a cheaper option that could have won.

    157 reviews were used while tuning prompts and never counted towards the result. A separate 80-review test set was labelled by hand before the model ran on it once, scored once, and never revised. The failure condition was set in advance: if the keyword baseline reached 90% of the agent’s quality, the honest conclusion was that this doesn’t need a language model.

    Blind test · 80 unseen reviews

    Counts in brackets
    Severity, not sentiment

    One question, asked in order

    Money lost or at risk → S1. Can’t do a core job → S2. Annoying but usable → S3. Everything else → S4. Star ratings, swearing and the word “scam” never raise the level. A published fee someone finds expensive is S3; money taken without agreement is S1.

    Human in the loop

    The agent doesn’t get the last word on money

    Every predicted S1, and every case where the agent and the baseline disagree about S1, routes to a person — 11% of reviews. An agent that quietly decides what counts as “someone lost money” is not a system I’d hand to a team.

    Model per job

    The strongest model only where judgement is needed

    Classification runs on the most capable model. The analyst above only orchestrates, since every number comes from code, so it runs on a cheaper tier. Defaulting to the best model everywhere is a cost decision disguised as a quality one.

    Where I was wrong. My first labelling pass marked 36% of reviews S1 and produced no S3 at all: I was grading anger, not consequence — the exact mistake this tool exists to fix. My two passes agreed on only 15 of 53 complaints. Later, reviewing 31 disagreements between me and the model, I changed 26 labels and 25 of them went the model’s way. That is automation bias, and it inflates the score, which is why the headline numbers come from a test set I labelled blind. All 27 decisions, including these, are in the repo.
    Code, taxonomy & decision log ↗

    Limits: Android only; people who hit a problem write reviews more often, so this compares wallets against each other rather than measuring satisfaction. Seven S1 cases in the test set is a small number — 7 of 7 gives a 65–100% interval. I found no clear case of users being tricked into paying; in reviews, “scam” is almost always anger or shorthand for an unauthorised charge, so that question needs support tickets instead.
